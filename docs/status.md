## 真实服务端到端走查（真实模型 + 真实知识库 + 真实工单存储与网关）

起一个 `create_app(governed=True)` 的服务，用 8 张工单走完整流程。验证到的行为：
- 笼统消息追问；查自己的订单（含物流）→ 工具结果进审核卡、引用是"系统查询结果"；查**别家店铺订单**和**不存在的订单**拿到**逐字相同**的回复；按店铺名查授权；需查账单 → 升级。
- 坐席批准后客户**还看不到任何回复**，确认后才发出，**重复确认 3 次客户仍只收到 1 条**，工单变 `resolved`。
- 升级后 `/handoff` 给出原因（含转交团队）、已执行动作、客户最后一句话。
- 越权：客户看他人工单 403、客户调审计 403、客户确认发送 403、别的坐席确认他人待发送 403、对已被他人负责且不在待审核的工单再审核 409。
- 这次走查**发现并修了一个真缺陷**：「我的店铺有问题」被追问"请补充电商平台名称"，答了平台之后系统仍不知道问题是什么；现在笼统消息优先问"具体遇到什么问题"（有回归测试）。
- 同一轮里我自己的脚本把"a2 审核了 a1 的工单返回 200"当成越权，查证后是脚本假设错了（那张工单从没被 a1 认领，a2 是第一个审核的所以自动认领）；用 a1 真的认领了的工单重测，结果符合预期。
