# 长期记忆约定（D5）

本项目**只留接口，不实现真正的记忆**（`src/carepilot/memory/spec.py` 已冻结）。读写约定直接沿用 spec 里的 5 条：

1. 写入时机：只在工单 resolved、且人工审核通过之后，由确定性代码写入；模型不能自己决定写什么。
2. 写什么：已确认的用户偏好（如「习惯用企业版」）、已验证有效的处理方案摘要。**不写**原始消息、手机号等敏感信息、未经审核的模型回复。
3. 读取：只作为「不可信的背景上下文」放进提示词，和检索到的知识库内容同等对待，不能改变工具调用策略。
4. 命名空间：每条记录归属一个 `user_id`，读取时必须带 `user_id`，不能跨用户读。
5. 过期：每条记录必须有 `ttl_seconds`，或显式声明 `permanent`。

为什么现在不做：记忆会引入跨工单的数据一致性、隐私和撤销问题，而且当前评估集无法衡量它带来的收益；没有评测的“智能”不符合本项目“可评估、可控”的目标。现在用 `NullMemoryStore` 占位，接口成本为零。

以后接入的第一步：先实现一个带 `user_id` 命名空间和 TTL 的 `SQLiteMemoryStore`，只落盘“人工审核通过后的偏好/方案摘要”，并给每条记录记 `source_run_id` 以便撤销；读取端只把它拼进提示词，不接进任何工具决策路径。
