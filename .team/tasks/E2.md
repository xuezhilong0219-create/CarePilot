# 任务 E2：评估集生成脚本

负责人：DeepSeek Harness（dsh）。先读 `.team/TEAM.md`。

## 背景

没有真实的历史工单，所以要用知识库反向合成评估集：抽样文档 → 让 LLM 以**客户的口吻**写一条工单 → 该文档就是标准答案。
这种方式天然有偏（问题和原文用词容易重合，会让 BM25 虚高），所以**必须防止照抄**。再配一批"知识库里没有答案"的样本，用来测拒答。
你只写**生成脚本**；真实的生成运行由 Claude 在清洗好的知识库上执行，你开发时只能用夹具和假 LLM。数据格式见 `src/carepilot/evaluation/schema.py`。

## 要做的事

写 `eval/gen_dataset.py`（命令行）和它依赖的 `src/carepilot/evaluation/gen_core.py`（可测试的纯逻辑）。

命令行：`--kb-dir data/kb_real --n-answerable 120 --n-unanswerable 30 --seed 42 --out eval/real/dataset.jsonl --model qwen3.8-flash --concurrency 8 [--dry-run]`

**1. 抽样**：
- 候选文档 = manifest 里 `kept=true`、flags 不含 `release_note` 和 `short`、`chars >= 300` 的文档。
- 分层：按 `top_dir` 分配名额，名额与该目录候选数的**平方根**成正比（让小目录也有代表），单个目录不超过总数的 35%，`慧策价值传递素材仓库` 和 `原掌上百科（Wiki）内部使用` 合计不超过 15%。用 `--seed` 固定随机性，同一个 seed 结果完全一致。

**2. 类别标签**（确定性，不让 LLM 判断）`category_for(top_dir, title)`：
- `top_dir == "平台对接_店铺授权"` → `platform_integration`；
- `top_dir in {"物流对接", "第三方仓对接", "仓储对接"}` → `warehouse_logistics`；
- title 含 `规则|政策|公告|通知|变更` → `rule_change`；
- 其余 → `feature_howto`。

**3. 可答样本**：每篇抽中的文档调用一次 LLM（`carepilot.llm.get_llm` + `StructuredLLM`，对一个你定义的 pydantic 输出模型；用 `Settings(llm_fast_model=args.model)` 指定模型）。提示词要求：
- 写一条商家发给售后的消息，口语化，15 到 80 个字，仅凭这篇文档能回答；
- 如果文档里有典型报错提示，可以让客户把报错原文贴进去（逐字）；
- **不能照抄文档标题，也不能照抄文档里的完整句子**；
- 同时输出 `severity`（low/medium/high/critical）、`platform_name`、`feature_name`、`partner_name`、`error_text`（都必须是出现在这条消息里的原文，没有就是 null）。
- 文档只给模型看标题 + 前 2500 字。

**4. 防照抄校验**（`gen_core.py`，必须单测）：生成的 `question` 与文档正文（去掉其中 `error_text` 部分之后）的**最长公共子串 ≥ 12 个字符**则拒收；长度不在 [12, 100] 拒收；`error_text` 不在 `question` 里拒收；与已有样本的问题完全重复拒收。拒收后最多重试 2 次（重试时 temperature 调高）。仍失败就丢掉这篇并换备选文档，保证最终数量足够；统计各种拒收原因的次数并打印。

**5. 不可答样本**（不依赖文档）：
- `n_unanswerable` 的 2/3 是 `data_exception`：客户问自己的某笔订单、某个库存数字、某张账单为什么不对，必须看客户数据才能回答（让 LLM 生成多条，要求彼此差异大，涉及不同平台和功能）；
- 1/3 是 `other`：闲聊、与 ERP 无关的问题、或要求办理产品之外的事项。
- 这些样本 `answerable=false`、`gold_doc_ids=[]`、`gold_title_keys=[]`。

**6. 其他**：
- 可答样本 `gold_doc_ids=[doc_id]`、`gold_title_keys=[title_key]`；`qid` 形如 `q0001`；`source="generated"`。
- 每次 LLM 调用的结果缓存到 `eval/real/cache/gen/<输入哈希>.json`，重跑不重复花钱；并发用线程池。
- `--dry-run`：不调用 LLM，只打印抽样结果（各目录名额、抽到的文档标题）和一条完整的提示词样例，并估算调用次数和大致 token 数。
- 同时输出 `eval/real/dataset_review.md`：随机 25 条样本，每条列出 qid、问题、标准答案文档的路径、该文档开头 200 字，供人工抽查。

## 文件归属

`eval/gen_dataset.py`、`src/carepilot/evaluation/gen_core.py`、`tests/test_gen_dataset.py`。
`schema.py` 是冻结的，别改；`evaluation/` 下其他文件是别的 worker 的。

## 验收

- `uv run pytest -q` 全绿，**测试不调用真实 LLM**：用假 `StructuredLLM` 返回预设输出。
- 测试覆盖：分层抽样（名额之和、各目录上限、seed 可复现）、`category_for` 四种分支、最长公共子串校验（含边界：恰好 12 与 11）、拒收后重试与换文档、缓存命中不再调用 LLM、输出 JSONL 能被 `load_dataset` 读回且字段合法。
- 在 `data/kb/` 示例数据上 `--dry-run` 能跑通（示例数据没有 manifest，你需要在夹具里造一个小 manifest 目录来测，脚本对缺 manifest 的目录要给出清晰的报错）。

## 不要做

不要调用真实 LLM（单测和验收都不用）；不要改 `graph/`、`retrieval/`、`api/`；不要实现评估指标。
