# 任务 E1：评估指标与评估脚本

负责人：opencode。先读 `.team/TEAM.md`。

## 背景

评估是这个项目最重要的部分：面试时要拿出"调参前后"的对比数字。你负责**指标计算和运行脚本**（评估集的生成由别的 worker 做，格式见 `src/carepilot/evaluation/schema.py`）。
真实评估集和报告都在 `eval/real/`（已被 gitignore），你在开发时只能用自己造的小数据。

## 要做的事

1. **`src/carepilot/evaluation/metrics.py`**（纯函数，无 IO，易测）：
   - 检索：`hit_at_k`（严格 doc_id / 宽松 title_key 两档）、`reciprocal_rank`、`recall_at_k`，以及对一批样本聚合；`percentile(values, p)`。
   - 一个 chunk 级的结果列表要先折叠成文档级的排序（同一文档多个 chunk 只算它最靠前的那次）再算 hit@k 和 MRR。
   - 分诊：`category` 准确率 + 混淆矩阵（字典形式）；`severity` 精确准确率和"相差不超过一档"准确率；实体抽取准确率（`platform_name / feature_name / partner_name`：期望值非 None 才计入，比较时做归一化——去空白、小写、互相包含也算对；`error_text` 要求预测值出现在客户原话里，且与期望值的重合率 ≥ 0.8）。
   - 回复：对 `answerable=true` 的样本算 `answer_rate`（resolution 为 auto_reply 的比例）和 `citation_hit_rate`（被引用的 chunk 的 doc_id 或 title_key 命中答案）；对 `answerable=false` 的样本算 `correct_refusal_rate`（resolution 不是 auto_reply）；以及整体的"错误放行率"（不该答却答了的数量/总数）。
2. **`src/carepilot/evaluation/runners.py`**：
   - `run_retrieval(items, retriever, k=10, query_mode="raw"|"triaged")`：`raw` 直接用 `question`；`triaged` 用 `carepilot.graph.nodes.build_query` 配合样本里的期望实体（隔离检索和分诊误差）。每条记录检索耗时。
   - `run_pipeline(items, settings, retriever, models=None, concurrency=4)`：对每条样本依次调用 `make_nodes(...)` 返回的 `classify`、`retrieve`、`draft_reply`（缺信息则按图的逻辑停在 `ask_for_info`），**不走 interrupt**。用线程池并发。收集每个节点的耗时，单条出错不能让整批失败（记录错误并计入 `errors`）。
3. **命令行脚本**（`eval/` 目录）：
   - `eval/run_retrieval.py --dataset eval/real/dataset.jsonl --kb-dir data/kb_real --retriever bm25 [--exclude-dirs a,b] [--exclude-flags x,y] [--k 10] [--query-mode raw|triaged|both] [--name 实验名] [--limit N]`。检索器通过 `carepilot.retrieval.factory.build_retriever`（接口见 TEAM.md；这个模块由别的 worker 实现，**你在函数内部延迟 import**，单测里用假检索器）。
   - `eval/run_pipeline.py --dataset ... --kb-dir ... --retriever ... [--triage-model M] [--draft-model M] [--limit N] [--concurrency 4] [--name 实验名]`：模型覆盖通过 `Settings` 的 `llm_fast_model` / `llm_main_model` 字段实现。
   - 两个脚本都把结果写到 `eval/real/reports/<时间戳>_<name>.json`（汇总指标 + 配置 + 数据集条数）和同名的 `.items.jsonl`（逐条明细，方便错误分析），并在终端打印一张 markdown 表。
   - `eval/compare.py 报告1.json 报告2.json ...`：并排打印各报告的核心指标，同时显示相对第一份的差值。
4. 公共的小工具（读写报告、打表）放 `src/carepilot/evaluation/report.py`。

## 文件归属

`src/carepilot/evaluation/`（**除 `schema.py` 外**）、`eval/run_retrieval.py`、`eval/run_pipeline.py`、`eval/compare.py`、`tests/test_evaluation.py`。

## 验收

- `uv run pytest -q` 全绿。
- 指标函数全部有**手算过期望值**的用例：至少覆盖——同一文档多 chunk 折叠、严格未命中但宽松命中、`k` 大于结果数、空结果、没有任何 answerable 样本时不除零、实体抽取的归一化三种情形。
- `run_pipeline` 用假 `Models` 和假检索器跑通一个 6 条样本的小数据集（覆盖：正常回复、缺信息、检索为空、拒答、单条抛异常），断言汇总指标等于手算值。
- `run_retrieval.py` 用 `data/kb/` 示例数据和你造的 5 条样本跑通一次（`--retriever bm25`；如果 `factory` 还没合并进来，用 `--help` 验证参数，并在报告里说明）。
